# 화면 정지·포인터 소실 재검토 — 2026-10-12

## 확인된 사실

- 사용자 보고: 화면 1이 멈추고 포인터가 사라졌으며 키 입력으로 복구하지 못해 재부팅함.
- 기존 LOCAL-CHECKS.md: 라이브 줌 뒤 Responding=false, 프로세스 종료 및 커서 복원 API 성공 뒤에도 실제 포인터 복구 미확인.
- 이번에는 기존 엔진을 실행하거나 화면 정지 현상을 재현하지 않음.
- Windows 이벤트 로그 조회는 접근 제한으로 실패. 당시 덤프와 정지 스택은 확보하지 못함.

## 코드에서 확인한 취약 지점

1. native.rs의 setup은 MagInitialize, 확대 창 생성, 필터·변환·원본 설정을 수행한 뒤 반환한다. Guardian::start는 setup 반환 이후 호출되므로 초기화 중 정지를 감시하지 못한다.
2. 입력 훅 설치, 화면 처리, 단축키, FRAME_TIMER/WATCHDOG_TIMER가 같은 UI 메시지 스레드에 의존한다. 이 스레드가 멈추면 정상 종료와 5분 해제도 진행하지 못한다.
3. mouse_proc의 라이브 경로에서 MagShowSystemCursor 및 SendInput을 동기 호출한다. 정지·재진입 위험이 있는 구조이나, 이번 사고의 정확한 정지 API로 확정하지 않는다.
4. 정지 확대는 화면 전체를 덮고 이동 이외 마우스 이벤트를 삼킨다. 라이브 모드만 막아도 정지 확대·펜의 입력 훅은 남는다.
5. 별도 감시는 프로그램 종료 후 다시 Magnification API로 커서를 복원한다. 기존 사용자 보고상 API 성공과 실제 표시 복구가 일치하지 않았다.
6. README에 라이브 모드를 중단했다는 경고와 Ctrl+2로 실제 시험하라는 절차가 함께 있었다.

## 이번 변경

- 실행 진입점에서 native/guardian 모듈을 제외. 위험 코드는 조사용 원본으로만 유지.
- Magnification·입력·DWM·스레드 관련 windows-sys 기능 의존성 제거.
- 실행 시 일반 안내창만 표시하며 기존 모니터 옵션도 안내창으로 연결. 전역 단축키 없음.
- 기존 내부 실행 옵션을 명시적으로 거부. smoke는 콘솔 전용 검사로 변경.
- 복구 스크립트에서 커서 API 재호출 제거. 경로가 일치하는 작업 폴더 프로세스 종료만 수행.
- 이전 시험 절차를 보류하고 문서 상태를 통일.

## 범위와 다음 단계

이 변경은 사고 경로의 실행 차단이다. 확대·필기 기능 수정 완료 또는 실사용 안정성 확보로 표시하지 않는다. 입력과 캡처를 분리하고, 전역 커서 숨김을 없앤 새 엔진을 격리 환경에서 검증한 후 복구해야 한다. 감시 종료 테스트만으로 GPU/데스크톱 복구를 입증할 수 없다.
