# 로컬 검사 기록

날짜: 2026-10-12 (Asia/Seoul)

## 실패 보고 — 라이브 줌

- 사용자가 라이브 줌 진입 뒤 멈춤을 보고함.
- 해당 검증판의 프로세스 `Responding=false`를 확인하고 정확한 실행 경로를 대조하여 강제 종료함.
- 라이브 줌 검증 상태: **실패**. 아래 초기화 검사 통과는 라이브 사용 가능성을 의미하지 않음.
- 원인 확정 전 조치: 라이브 진입을 훅 설치·커서 숨김·확대 창 표시 이전에 차단. `--restore-cursor`와 별도 `npm run recover` 복구 명령 추가.
- 구조상 문제: UI/확대 처리와 저수준 입력 훅이 같은 메시지 스레드에 있으며, 훅 안에서 동기 입력 주입과 Magnification 호출을 수행함. 5분 타이머와 비상 단축키 역시 이 스레드에 의존함.
- 정확한 정지 API/스택은 확보하지 못했으므로 동기 호출 교착을 확정 원인으로 표시하지 않음.
- 재활성화 조건: 입력 훅의 독립 메시지 스레드와 비동기 전달, 확대 처리 분리, 독립 프로세스 감시/복구, 고의 스레드 정지 시 복구 검증 후 라이브 재검증.

## 긴급 수정 검증

- Ctrl+숫자 단축키로 변경. Ctrl+0은 별도 감시 프로세스의 비상 종료, Ctrl+8은 정상 확대 해제.
- 정지 줌 휠 확대·축소 추가. 훅은 휠 값을 메시지 큐로 전달하며 렌더링을 직접 호출하지 않음.
- 좌표·정밀 휠 누적 테스트 총 6개 통과. Clippy 통과.
- 숨긴 시험 창에서 `--guardian-test`로 UI 스레드를 고의 정지. 독립 감시 프로세스가 종료 코드 73으로 강제 종료함. 입력 훅·캡처·커서 숨김 없이 수행.
- 기존 PID 20896의 GetExitCodeProcess 결과는 0xffffffff로 종료 상태. 프로세스 객체가 일시적으로 열거되었으나 실행 중 상태(STILL_ACTIVE=259)는 아님.
- MagShowSystemCursor(true)와 현재 커서 모양 재로드 API는 성공하고 GetCursorInfo flags=1을 반환했지만, 사용자는 여전히 포인터가 안 보인다고 보고함. **실제 복구 미확인**. 보안 화면 전환 후 표시 여부를 확인 중.
- 포터블 안정성 문제가 배포 방식 때문이라는 근거는 없음. 필요 시 설치형으로 전환하도록 사용자 승인됨. UIAccess 서명 설치형 검토는 입력/캡처 스레드 문제 해결과 구분함.

## 의미하지 않는 것

숨겨진 창 검사는 확대 출력 픽셀·실제 마우스 입력·화상회의 수신 영상을 검사하지 않습니다. 마우스 훅과 입력 주입은 해당 검사에서 설치하거나 실행하지 않았습니다.

Zoom·Meet 수신, 라이브 직접 조작, 한글 IME, DPI 혼합, 4K, 성능, 절전·분리, 강제 종료 복구는 아직 **미검증**입니다. 제품 전체가 완성되거나 공유 관문을 통과했다고 표시하지 않습니다.

수신 검증 결과는 `docs/VALIDATION.md`에 기록한 뒤 다음 단계 진행 여부를 판단합니다.
